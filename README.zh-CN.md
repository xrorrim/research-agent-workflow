# 科研多智能体工作流（Research Agent Workflow）

[English](README.md) · 简体中文

一套用于**开放式科研任务**的五角色多智能体工作流。目标明确、但实现路径模糊的科研任务，往往需要多个 agent 分工协作：调研定方向、推进拆任务、实现跑实验、审核卡质量、汇总记笔记。本仓库把这套工作流打包成**四个可一键安装的版本**，覆盖两个平台（Claude Code / Codex）× 两个 prompt 版本（对照版 / 自动化版）。

四个版本刻意做成 **A/B 对照实验**的形式：同一套编排机制下，只有 prompt 本身不同，用来测量"prompt 优化"到底给 agent 的科研产出带来多少差异。

---

## 五个角色

| 角色 | 职责 | 关键边界 |
|------|------|---------|
| **角色1 · 调研者** | deep research + 与作者多轮讨论，一次选定一条技术路线 | 路线要**粗**——只写方向、可证伪假设、成功指标、里程碑；写细了会锁死角色2 的探索空间 |
| **角色2 · 方向推进者** | 把路线拆成具体实验任务，根据结果决定推进/调整/上报 | 唯一有权判断"路线走不通"的角色；判死需**多方验证** |
| **角色3 · 实现与运行者** | 写实验代码、准备 run.sh、整理交付结果 | 失败也要如实交付，不许粉饰 |
| **角色5 · 检查者** | 审核代码与实验设计 | 不通过 → 立即终止运行、清空本循环结果、打回重做 |
| **角色4 · 结果汇总者** | 写实验笔记、更新全局索引、做**合规判定** | 核查有无偷工减料、实验不对齐、数字不可溯源 |

角色1 并入主会话——你打开的那个对话就是角色1，也是你与整个系统**唯一**的交流界面。主会话同时兼任消息总线，自动驱动 R2→R3→R5→R4→R2 循环。

```
你(作者) ⇄ 主会话（角色1·调研者 + 消息总线）
                │ 自动派生 / 唤醒子代理
    ┌───────────┼───────────┬───────────┐
    ▼           ▼           ▼           ▼
 role2       role3       role5       role4
 方向推进     实现与运行    检查者       结果汇总
                │
                └─ 正式运行由主会话后台启动（nohup + pid 文件），
                   与 role5 审核并行；审核不过 → kill 运行、清空结果、打回重做
```

## 一个循环里发生什么（M1–M7 协议，自动化版）

| 消息 | 方向 | 内容 |
|------|------|------|
| M1 | 角色1 → R2 | 路线下达 |
| M2 | R2 → R3 | 任务下达（含可测量的验收标准） |
| M3 | R3 → R5 | 审核请求（含 commit、run.sh、预计时长；无新代码免审） |
| M4 | R5 → R3 | 审核结果；不通过 → 主会话 kill 运行、清空本循环结果、打回重做（3 次上限） |
| M5 | R3 → R4 | 结果交付（失败也如实交付，3 次运行失败上限） |
| M6 | R4 → R2 | 笔记归档 + 合规判定 |
| M7 | R2 → 角色1 | 路线上报（此时系统暂停找你讨论） |

系统只在三个时刻打扰你：**M7 路线上报**、**判死路线需确认**、**达标结题**。你随时可以主动插话，优先级最高。会话中断后新开会话说"继续循环"即可从消息存档恢复断点——**状态全在文件里，不依赖会话记忆**。

| Codex · 对照版 | Codex | 原始 prompt 基线 | [`科研工作流-Codex对照版.zip`](packages/科研工作流-Codex对照版.zip) |
| Codex · 自动化版 | Codex | 优化版 | [`科研工作流-自动化版-Codex-自安装.zip`](packages/科研工作流-自动化版-Codex-自安装.zip) |

**只想用**：选自动化版（对应平台）。
**想做 prompt 消融实验**：两版都装，装在**两个独立仓库**里跑同一课题。

### 对照版 vs 自动化版

| 维度 | 对照版（基线） | 自动化版（优化） |
|------|--------------|----------------|
| 角色记忆 | 持久子代理（延续同一实例，对应原设计的 5 个常驻会话） | 无状态子代理 + 文件记忆（`logbook/index.md`） |
| role2 工具 | 含网络检索（判死前须多方验证） | 无网络工具（深度调研归角色1） |
| 消息格式 | 无规定，自由文本 | M1–M7 固定字段 |
| 验收标准 / 循环编号 / 版本绑定 / 结果作废规则 / 笔记索引 | 无（原文未定义，**属于被测变量**） | 有 |
| 上报触发 | R2 自判"完成 / 不可实现" | 假设证伪 / 连续 3 循环无进展 / 每 5 循环例行对照 |
| 目录结构 | 仅 `messages/` | `docs/`、`logbook/`、`experiments/`、`results/`、`tests/` |

对照版的角色定义是**原始 prompt 原文照录**，只做了运行所需的机械适配；编排机制（自动化载体、边跑边审、后台运行、3 次保险丝阈值）与自动化版完全相同——这样两版的差异只剩 prompt 本身。每个包的 README 里有一份透明清单，逐条说明哪些是原文、哪些是 harness 添加。

## 模型分层（仅 Claude Code 两版）

算力向决策与实现倾斜，审核与记录降一级——"优先开发、弱化安检"：

| 角色 | model | effort | 配置在 |
|------|-------|--------|--------|
| 角色1 调研者（主会话） | `best` | `xhigh` | `.claude/settings.json` |
| 角色2 方向推进者 | `best` | `max` | agent frontmatter |
| 角色3 实现与运行者 | `best` | `max` | agent frontmatter |
| 角色5 检查者 | `opus` | `max` | agent frontmatter |
| 角色4 结果汇总者 | `opus` | `max` | agent frontmatter |

用的是**别名不是模型 ID**：`best` = 有权限就用当前最强模型（截至 2026-07 为 Fable 5），否则自动回落到最新 Opus；`opus` = 最新 Opus。模型换代时自动跟随，不用改任何文件——没有 Fable 权限的人 clone 下来照样能跑，只是顶层降为 Opus。

两版的模型配置**完全一致**，因此它不是 A/B 对照实验的被测变量。

**三个坑**：主会话 effort 只能到 `xhigh`（`max` 是会话级设置，配置文件不接受；要 `max` 得每次 `/effort max`）；`CLAUDE_CODE_EFFORT_LEVEL` 环境变量会压过 frontmatter，设了它 effort 分层全部失效；**不要开 ultracode**——它不是深度档位而是"`xhigh` + 自动编排 dynamic workflow"，会与本工作流自己的状态机争夺编排权。

需要 Claude Code **≥ 2.1.219**。对照版尤其敏感：它用 SendMessage 延续持久子代理，而 2.1.211 之前子代理的 `model:` 覆盖会在续接时静默退回主会话模型。

## 安装

> ⚠️ **不要把两个版本装进同一个仓库**——配置文件会互相覆盖。用两个独立仓库，或同一仓库的两个 worktree/分支。

### Claude Code（两版通用）

把 zip 放进你的项目仓库根目录，对 Claude Code 说：

```
解压 科研工作流-自动化版.zip 到当前目录，然后按 BOOTSTRAP.md 执行。
```

它会自己完成文件放置、建目录骨架、检查 git 并汇报验证清单，然后当场变身为角色1 向你要课题。

<details>
<summary>手动安装（等价三步）</summary>

1. `CLAUDE.md` → 仓库根目录；四个 `role*.md` 和 `settings.json` → `.claude/`
2. 建骨架：
   ```bash
   mkdir -p .claude/agents docs/route_archive logbook/messages experiments results tests
   touch logbook/index.md logbook/debt.md
   ```
3. 要求 Claude Code **v2.1.219+**

</details>

### Codex（两版通用）

**让 Codex 自己装**——把 zip 的绝对路径连同这句话交给位于目标项目根目录的 Codex：

```
请安全解压这个 ZIP 到临时目录，完整阅读解压目录根部的 BOOTSTRAP.md，
并按它把科研工作流安装到当前 git 项目；安装后在当前任务中立即按新 AGENTS.md 行事。
```

**或手动一键装**：解压后 macOS 双击 `install.command`，终端里跑 `./install.sh`（对照版是 `INSTALL.command`）。装完在项目根目录开一个新 Codex 任务，说：

```
把科研多智能体工作流安装到当前目录，然后按 research-workflow-automation 技能执行。
```

卸载：`codex plugin remove research-workflow-automation`（已生成的科研记录不会被删）。

## 使用

1. 在仓库目录启动 agent，**直接描述你的课题**——对面就是角色1，会做深度调研并与你多轮讨论；
2. 你确认路线后，它写好 `docs/route.md`、发出 M1，说"**开始循环**"即进入全自动实验循环；
3. 中断后新开会话说"**继续循环**"衔接断点。

**前置条件**：目标目录必须是 git 仓库（实验结果用 commit hash 绑定）。

## 运行建议

- 每个循环 ≈ 5–8 次子代理调用 + 主会话轮询，**token 消耗可观**。先用小任务跑 1–2 个循环观察质量，再放长任务。
- 每 5 个循环亲自读一遍 `logbook/index.md`，确认方向没漂移。
- 主会话上下文过长时可 `/compact`——协议设计上状态全在文件里，压缩不丢状态。
- 想改回"先审后跑"（串行）、调整 3 次保险丝阈值或 5 循环对照周期：都是配置文件里的明文数字，直接改。
- **工程债**（安全加固、异常兜底、系统补全、重构）一律记进 `logbook/debt.md` 留给人工处理，agent 绝不为此派任务。

## 做对照实验

- 同一课题、同一条起点路线、相近的循环数下分别跑两版；
- 对比维度：达成同一里程碑所需循环数；返工率（审核打回、合规不通过、保险丝触发次数）；笔记与结论的可读性/可信度；token 消耗；是否跑偏或原地打转；
- 两边都保留完整消息存档（对照版 `messages/`，自动化版 `logbook/messages/`），可逐循环复盘；
- 建议先各跑 2–3 个循环的小任务定性看差异，再决定是否上长任务。

## 仓库结构

```
packages/    四个一键安装 zip（发布物，安装就用这些）
prompts/     zip 解压后的全部 prompt 源文件，便于在线浏览与 diff
  claude-code/{baseline,optimized}/
  codex/{baseline,optimized}/
```

`prompts/` 是 `packages/` 的解压镜像，方便直接在 GitHub 上读 prompt、比对两版差异；实际安装请用 `packages/` 里的 zip。Codex 自动化版另附 [`ADAPTATION-AUDIT.md`](prompts/codex/optimized/ADAPTATION-AUDIT.md)，逐条审计了 Claude Code → Codex 的平台适配改动（保证只改平台差异，不改科研 prompt）。
