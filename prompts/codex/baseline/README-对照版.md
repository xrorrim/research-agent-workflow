# 科研多智能体工作流 · Codex 对照版（原始 prompt 基线）

用途：与优化版做 **A/B 对照实验**，测试 prompt 优化对 agent 结果的影响。本包的角色定义是作者的原始 prompt **原文照录**，编排机制（自动化载体、边跑边审、后台运行、保险丝阈值）与优化版相同——这样两包的差异只剩 prompt 本身。

## ⚠️ 安装警告

Codex 插件可以全局安装，但**不要在同一个仓库中同时运行对照版与优化版**。用两个独立仓库，或同一仓库的两个 worktree/分支，分别运行两版。

## 一键安装

解压 zip 后，在 Finder 中双击：

```text
INSTALL.command
```

或在 Codex 中打开解压目录并说：

```text
按 BOOTSTRAP.md 安装科研工作流对照版，然后在我的项目仓库中启动。
```

插件安装后，在新的 Codex task 中调用 `$research-workflow-control:run-workflow`，或直接描述课题并明确要求使用“科研工作流·对照版”。

角色2–5 的文件在 `plugins/research-workflow-control/skills/run-workflow/references/` 内。

## 哪些是原文、哪些是 harness 添加（透明清单）

**原文照录（被测对象）**：总述与通信条例；角色1–5 的全部角色定义文字，一字未改。另含两处**作者修订**（作者认可的正确性修正，同属被测 prompt）：①原文的"其他agent"明确不存在——安全性保障开发、系统补全归作者（人类），agent 禁做、禁转交；②"不可实现"的判断标准由"严格逻辑证明"放松为**多方验证**（检索他人已有实现如加速 blog/论文/开源代码 + 严格理论计算对比），不能试一试就放弃；上报"已完成/不可实现"后系统停止等作者。

**harness 添加（两版一致或已注明差异，不属于被测 prompt）**：

1. 每个角色文件顶部的【Codex 运行环境说明】——只说明消息如何物理流转（主 agent 代为转发、正式运行由主 agent 后台启动以便审核可中断）；
2. 保险丝：同一任务审核打回累计 3 次、或运行失败累计 3 次 → 暂停询问作者（阈值与优化版一致）；
3. 未定义流向不暂停：因作者修订①该场景理论上不再出现；若出现罕见的未定义消息，按最合理解释就近路由并存档标注，不中断循环（暂停只发生在保险丝、角色2 上报、作者插话时）；
4. 消息自动存档到 `messages/`（供断点恢复与你查阅，不要求角色遵循任何格式）；
5. 子 agent 工具权限与原 Claude Code 包的对应角色一致；工具名称机械映射为 Codex 的文件、shell 与网页工具。

## 与优化版的机制差异（解读结果时注意）

| 维度 | 对照版（本包） | 优化版 |
|------|--------------|--------|
| 角色记忆 | **持久子 agent**（`followup_task` 延续同一实例，对应原设计的 5 个常驻会话） | 无状态子 agent + 文件记忆（index.md） |
| role2 工具 | 含 Codex 网页搜索/打开工具（作者修订②要求多方检索验证） | 无网络工具（判死前的深度调研在角色1） |
| 消息格式 | 无规定，自由文本 | M1–M7 固定字段 |
| 验收标准 / 循环编号 / 版本绑定 / 结果作废规则 / 笔记索引 | 无（原文未定义，**属于被测变量**） | 有 |
| 上报触发 | R2 自判"完成/不可实现"（须多方验证：检索他人实现 + 理论计算对比） | 假设证伪 / 连续 3 循环无进展 / 每 5 循环例行对照 |

## 对照实验建议

- 同一课题、同一条起点路线、相近的循环数下分别跑两版；
- 对比维度参考：达成同一里程碑所需循环数；返工率（审核打回、合规不通过、保险丝触发次数）；笔记与结论的可读性/可信度；token 消耗；是否跑偏或原地打转；
- 两边的 `messages/`（对照版）与 `logbook/messages/`（优化版）都保留完整消息存档，可逐循环复盘；
- 建议先各跑 2–3 个循环的小任务定性看差异，再决定是否上长任务。

## 使用

在项目仓库中打开 Codex，调用 `$research-workflow-control:run-workflow` 并描述课题（对面是角色1），确认路线后说"开始循环"；中断后新 task 调用同一技能并说"继续循环"。你随时插话，优先级最高。
